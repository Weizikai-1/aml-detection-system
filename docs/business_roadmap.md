## 二、B2-3 阶段：数据血缘追踪

### 2.1 目标
实现端到端"报告→证据→规则→原始交易→导入批次"的可追溯链，满足监管审计要求。

### 2.2 功能清单

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 血缘记录生成 | 每次分析自动生成血缘记录，关联所有关键节点 | P0 |
| 报告级追溯 | 从 STR 报告反查命中规则、证据交易、原始数据 | P0 |
| 交易级追溯 | 从单笔交易正向查参与的所有报告和规则 | P1 |
| 批次级追溯 | 从导入批次查所有分析结果和报告 | P1 |
| 血缘完整性校验 | 哈希链保护血缘记录，防止篡改 | P1 |
| 血缘检索 API | 提供按报告/交易/批次的血缘查询接口 | P1 |
| 过期清理 | 自动清理超出血缘保留期的记录 | P2 |

### 2.3 数据模型
```
LineageRecord {
  lineage_id: str          # 血缘记录ID
  execution_id: str        # 分析执行ID
  batch_id: str            # 数据导入批次
  report_id: str           # STR报告ID
  transaction_ids: [str]   # 涉及的原始交易ID
  rule_hits: [RuleHit]     # 命中的规则及证据
  evidence_chain: [str]    # 证据链节点
  timestamp: datetime      # 生成时间
  prev_hash: str           # 前一条记录哈希
  current_hash: str        # 当前记录哈希
}
```

## 三、B3 阶段：高级可视化与分析

### 3.1 B3-1：关联图谱可视化

**目标**: 将可疑交易网络以交互式图谱形式展示，辅助分析师快速识别团伙结构。

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 账户级图谱 | 展示账户间资金流向，节点大小=交易金额，颜色=风险等级 | P0 |
| 团伙级图谱 | 展示社区发现结果，标注核心账户和边缘账户 | P0 |
| 交易时间轴 | 按时间展示交易序列，标注异常模式 | P1 |
| 交互功能 | 缩放、拖拽、点击查看详情、筛选 | P0 |
| 导出功能 | 导出为图片/HTML | P2 |
| 多视图切换 | 账户视图/团伙视图/时序视图 | P1 |

### 3.2 B3-2：智能报告模板自适应

**目标**: 根据案件类型自动选择最优报告模板，提升报告专业性和可读性。

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 模板分类 | 分拆型/对敲型/虚拟货币型/跨境型/混合型 5套模板 | P0 |
| 自动识别 | 基于命中规则和交易模式自动选择模板 | P0 |
| 证据链排序 | 按模板侧重不同排序证据，突出关键疑点 | P1 |
| 专业术语库 | 不同案件类型使用对应的监管术语 | P1 |
| 模板可配置 | 支持自定义模板和字段映射 | P2 |

### 3.3 B3-3：多机构联邦分析框架

**目标**: 实现跨机构数据安全共享，在不泄露原始数据的前提下联合分析跨机构洗钱网络。

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 数据脱敏共享 | 差分隐私 + 哈希脱敏，保护客户隐私 | P0 |
| 联邦GNN训练 | FedAvg 参数聚合，不传输原始数据 | P1 |
| 跨机构案件映射 | 统一案件ID映射，避免重复上报 | P1 |
| 审计日志同步 | 跨机构操作审计，满足监管要求 | P2 |
| 机构接入管理 | 机构注册、权限控制、数据范围 | P2 |

## 五、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| GNN 依赖太重(torch/pyg) | 部署困难 | 提供纯 networkx 降级方案，GNN 为可选增强 |
| 图谱数据量大卡顿 | 用户体验差 | 分页加载 + 节点聚合 + WebGL 渲染 |
| 联邦分析场景复杂 | 开发周期长 | 先做框架和核心算法，后续迭代完善 |
| 模板数量多维护难 | 一致性问题 | 提取公共模板骨架，差异化部分配置化 |
